================================================================

IMPORTANT INTERPRETATION
------------------------
If the user says "Open law," interpret that as OpenClaw unless explicitly corrected.

This is an implementation runbook. It is not a market opinion, not a generic risk memo, and not a request to make Roi Snips conservative. The goal is to improve Roi Snips so it finds volatile, asymmetric, non-blue-chip, catalyst-driven stocks and produces auditable trade packets and no-order validation artifacts.

This runbook does not authorize live orders by itself. It tells the agent what to implement and how to prove the implementation. Live arming remains a separate operator decision.


1. CORE MISSION
===============

Roi Snips must behave like a fast, cunning catalyst hunter and tape-aware trading system.

It must not behave like:
- a safe blue-chip stock picker
- a generic watchlist generator
- a passive news summarizer
- a single-model LLM stock picker
- a bot that picks the same prior winner after the move is mostly gone
- a system that watches the first minute, fails to buy, and then goes dead before the real second-leg move

The desired behavior is:

1. Find the weird runner early.
2. Validate the catalyst with official/structured evidence.
3. Track whether the current entry is still fresh or already extended.
4. Mark one research_leader.
5. Mark executable_primary only if current price/tape/entry quality is valid.
6. If extended but still valid, classify as SECOND_LEG_WATCH.
7. Keep monitoring through 11:00 ET for ORB, VWAP reclaim, premarket-high reclaim, and second-leg continuation.
8. Generate same-style volatile backups instead of mega-cap filler.
9. Preserve full artifacts so every decision can be audited.
10. Let deterministic code, not an LLM, own execution decisions.


2. NON-NEGOTIABLE DESIGN PRINCIPLES
===================================

2.1 Research and execution are different
----------------------------------------

The system must maintain separate fields:

- research_leader
- executable_primary
- watch_only
- second_leg_watch
- no_trade_extended
- anti_chase_state
- opportunity_lifecycle_state
- entry_viability_score

The best research idea is not automatically a buy.

Example:

INFQ can be the research_leader because the catalyst is strong, the theme is hot, and premarket volume is real. But if INFQ is already up 40%+ and near earlier targets, it may be SECOND_LEG_WATCH or NO_TRADE_EXTENDED until a clean reset/reclaim/continuation appears.

2.2 Broad discovery must happen before strict filtering
-------------------------------------------------------

Do not let deterministic filters kill weird volatile names before they are enriched.

Required discovery order:

1. Raw deterministic discovery.
2. Broad Pro-style AI-assisted discovery.
3. Evidence packet construction.
4. Source-lane status audit.
5. Market/tape overlay.
6. Social velocity overlay.
7. Same-style backup generation.
8. Research leader vs executable primary split.
9. Optional governed deep-research shortlist synthesis.
10. Final packet.
11. Opening/second-leg monitoring.

2.3 No lazy no-trade
--------------------

No-trade is allowed, but not lazily.

No-trade is valid only after the system has attempted:

- top premarket mover scan
- high relative-volume scan
- high premarket dollar-volume scan
- official catalyst scan
- structured news scan
- broad Pro-style AI discovery pass
- same-style backup pool construction
- source_lane_status artifact generation
- top rejected candidate explanations

2.4 No mega-cap fallback unless exceptional
-------------------------------------------

Mega-cap/default tickers include:

AAPL, AMZN, AMD, GOOG, GOOGL, META, MSFT, NFLX, NVDA, PLTR, QQQ, SMCI, SPY, TSLA

These must not appear as A-tier or primary backups unless:

- no viable same-style volatile backups exist, or
- the mega-cap has an exceptional same-day catalyst and exceptional tape.

If a mega-cap backup is used, the report must explicitly say:

- why same-style backups were unavailable
- which source lanes failed or produced no candidates
- why the mega-cap backup is still useful

2.5 Browser lanes are evidence tools, not market-data or execution tools
------------------------------------------------------------------------

Browser lanes, Playwright, Stagehand, Crawl4AI, and Firecrawl are useful for source inspection and extraction. They must not be the primary quote, bar, tape, or order source.

Primary market/tape truth remains Alpaca SIP quote/trade/bar data or the configured official market-data vendor.

2.6 Deep research is powerful but not a last-second execution tool
------------------------------------------------------------------

Governed deep research can help synthesize candidates and explain evidence. It must not decide live order placement.

Deep research must never override:

- missing/stale data checks
- one-position rule
- open-order checks
- cash/settled cash checks
- kill switch
- disable-new-entries guard
- spread/tape invalidation
- exit-manager requirement

2.7 High risk is allowed; broken plumbing is not
------------------------------------------------

The system may prefer volatile, speculative, small/mid/micro-cap names.

But it must still hard-block mechanical failures:

- missing live market data
- stale quotes
- missing bid/ask
- active halt/no quote
- broker/account failure
- broker state mismatch
- duplicate order
- open position already exists
- open bracket/order already exists
- insufficient cash/settled cash
- kill switch active
- disable entries active
- no LIVE_ARMED state for live submission
- exit manager unavailable

Everything else is a score, size, entry-mode, or exit-urgency adjustment.


3. CURRENT GAP SUMMARY TO FIX
=============================

The latest audit/review history indicates these still need proof or improvement:

1. Source code has many right pieces, but artifact proof is incomplete.
2. Morning JSON was stale and did not prove research_leader/executable_primary/anti_chase_state/source_lane_status.
3. source_lane_status generation exists in code, but the run artifact was missing.
4. Backup breadth remains weak; prior outputs used mega-cap/default filler.
5. Captured-tape continuation replay has not proven the 09:46-style move is catchable.
6. Opening stream and continuation monitor orchestration must be concurrent or precisely handed off at 09:35.
7. Broad Pro-style AI discovery must run before strict filtering, not only after deterministic shortlist creation.
8. First-seen tracking must be implemented so Roi knows whether it found a runner early or late.
9. Same prior winner / stale winner detection must prevent blindly picking yesterday's runner after the trade has already paid.
10. Final reports must explain why no proposal happened, not just say no proposal_count.

PHASE 6: Strengthen lifecycle and anti-chase classification
-----------------------------------------------------------

Patch:

- src/research/lifecycle.py
- src/research/market_overlay.py
- src/workflows/premarket_pipeline.py
- src/strategy/second_leg_continuation.py
- tests/test_lifecycle_classification.py
- tests/test_anti_chase.py

Lifecycle states must include:

- EARLY_CATALYST_DISCOVERY
- PREMARKET_BUILDING
- OPENING_DRIVE_ACTIVE
- EXTENDED_CHASE
- SECOND_LEG_WATCH
- SECOND_LEG_RESET
- OPENING_CONTINUATION_ACTIVE
- SECOND_LEG_CONTINUATION_ACTIVE
- EXHAUSTED_OR_DISTRIBUTING
- STALE_PRIOR_WINNER
- NO_TRADE_EXTENDED

Classification rules:

EARLY_CATALYST_DISCOVERY:
- catalyst found before material price move
- first_seen_gap_pct modest
- volume beginning to build

PREMARKET_BUILDING:
- catalyst validated
- premarket volume/dollar volume rising
- gap not so extended that entry is chase-only

OPENING_DRIVE_ACTIVE:
- first 5s/10s/30s/60s tape confirms drive

EXTENDED_CHASE:
- price far above buy zone and near/above initial targets
- no reset yet

SECOND_LEG_WATCH:
- strong research leader
- extended or first burst failed
- catalyst intact
- needs reset/reclaim/continuation

SECOND_LEG_RESET:
- stock has pulled back or based
- holds VWAP/support/local low
- volume no longer dumping

OPENING_CONTINUATION_ACTIVE:
- post-09:35 ORB/VWAP/premarket-high reclaim confirms continuation

EXHAUSTED_OR_DISTRIBUTING:
- loses VWAP/support on heavy volume
- repeated failed reclaims
- bid collapses or spread explodes

STALE_PRIOR_WINNER:
- was a prior-day/earlier winner
- no fresh catalyst or no second-leg setup

NO_TRADE_EXTENDED:
- too extended, no reset, no continuation confirmation

Acceptance tests:

1. +40% validated premarket runner becomes SECOND_LEG_WATCH, not automatic buy.
2. +40% unvalidated runner becomes NO_TRADE_EXTENDED.
3. Prior winner with no new catalyst becomes STALE_PRIOR_WINNER.
4. Candidate that bases then reclaims VWAP on expanding volume becomes OPENING_CONTINUATION_ACTIVE.
5. Candidate that loses VWAP and fails two reclaims becomes EXHAUSTED_OR_DISTRIBUTING.
